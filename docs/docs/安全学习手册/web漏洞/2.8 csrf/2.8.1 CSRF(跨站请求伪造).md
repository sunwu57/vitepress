**<font style="color:rgb(38, 38, 38);">CSRF 危害：</font>**<font style="color:rgb(38, 38, 38);">  
●修改个人信息/帐号密码  
●发送伪造的业务请求  
●关注他人的社交帐号,推送博文  
●在用户非自愿,不知情的情况下提交请求  
●获取信用卡等信息  
</font>**<font style="color:rgb(38, 38, 38);">触发条件：</font>**<font style="color:rgb(38, 38, 38);">  
①用户某一网站处于登陆状态（即身份验证状态暂未过期）  
②用户访问了一黑客精心构造的带有特殊url访问请求的网站  
③服务器无二次身份验证机制  
  
</font>**<font style="color:rgb(38, 38, 38);">漏洞核心：</font>**<font style="color:rgb(38, 38, 38);">  
服务器对用户身份验证不够严格（即缺少二次验证（二次验证加入验证码）或者特殊的身份验证（token））  
  
</font>**<font style="color:rgb(38, 38, 38);">漏洞验证：</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">一般在用户信息更新页面</font>**<font style="color:rgb(38, 38, 38);">，利用Burpsuite抓包，利用工具内部的功能生成CSRF的POC（这个POC也可以自定义），然后将生成的HTML代码放在一公网服务器下，由用户访问然后查看确认最后是否触发漏洞。  
  
</font>**<font style="color:rgb(38, 38, 38);">防御方法：</font>**<font style="color:rgb(38, 38, 38);">  
1设置随机Token。如果设置这个参数就不存在漏洞，一般在数据包中就可以直接判断出。（</font>**<font style="color:rgb(232, 50, 60);">推荐这个</font>**<font style="color:rgb(38, 38, 38);">）  
2检测referer来源。但是一般可伪造。</font>

# **<font style="color:rgb(38, 38, 38);">原理</font>**
<font style="color:rgb(51, 51, 51);">CSRF</font><font style="color:rgb(38, 38, 38);">，全称Cross-site request forgery，翻译过来就是跨站请求伪造  
  
</font><font style="color:rgb(38, 38, 38);">指利用受害者尚未失效的身份认证信息（cookie、会话等），诱骗其点击恶意链接或者访问包含攻击代码的页面，在受害人不知情的情况下</font>**<font style="color:rgb(0, 0, 0);">以受害者的身份</font>**<font style="color:rgb(38, 38, 38);">向（身份认证信息所对应的）服务器发送请求，从而完成非法操作(如转账、改密等）  
  
</font><font style="color:rgb(38, 38, 38);">CSRF与XSS最大的区别就在于，</font>**<font style="color:rgb(0, 0, 0);">CSRF并没有盗取cookie而是直接利用</font>**

### **<font style="color:rgb(38, 38, 38);">token讲解</font>**
<font style="color:rgb(38, 38, 38);">要抵御 CSRF，关键在于在请求中放入黑客所</font>**<font style="color:rgb(245, 34, 45);">不能伪造的信息</font>**<font style="color:rgb(38, 38, 38);">，并且该信息</font>**<font style="color:rgb(245, 34, 45);">不存在于 cookie 之中</font>**<font style="color:rgb(38, 38, 38);">  
  
</font><font style="color:rgb(38, 38, 38);">token：</font><font style="color:rgb(38, 38, 38);">访问改密页面时，</font>**<font style="color:rgb(0, 0, 0);">服务器返回的一个随机的值</font>**<font style="color:rgb(38, 38, 38);">  
  
</font><font style="color:rgb(77, 77, 77);">当浏览器向服务器发起请求时，需要提交token参数，而服务器在收到请求时，</font>**<font style="color:rgb(0, 0, 0);">会优先检查token</font>**<font style="color:rgb(77, 77, 77);">，只有token正确，才会处理客户端的请求</font><font style="color:rgb(38, 38, 38);">  
  
</font><font style="color:rgb(77, 77, 77);">但这种方法的</font>**<font style="color:rgb(0, 0, 0);">难点在于如何把 token 以参数的形式加入请求</font>**<font style="color:rgb(38, 38, 38);">  
  
</font><font style="color:rgb(77, 77, 77);">对于 </font>**<font style="color:rgb(0, 0, 0);">GET </font>**<font style="color:rgb(77, 77, 77);">请求：token 将附在请求地址之后，这样 URL 就变成 http://url?csrftoken=tokenvalue</font><font style="color:rgb(38, 38, 38);">  
  
</font><font style="color:rgb(77, 77, 77);">对于</font>**<font style="color:rgb(0, 0, 0);"> POST</font>**<font style="color:rgb(77, 77, 77);"> 请求来说，要在 form 的最后加上 ，这样就把 token 以参数的形式加入请求了</font><font style="color:rgb(38, 38, 38);">  
</font>
