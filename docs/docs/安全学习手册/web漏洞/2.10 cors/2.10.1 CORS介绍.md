<font style="color:rgb(38, 38, 38);">阅读本文，你需要首先知道：  
1浏览器的同源策略  
2跨域问题  
3JSONP原理  
4cookie原理  
  
JSONP并不是一个好的跨域解决方案，它至少有着下面两个严重问题：  
1. </font>**<font style="color:rgb(38, 38, 38);">会打乱服务器的消息格式</font>**<font style="color:rgb(38, 38, 38);">：JSONP要求服务器响应一段JS代码，但在非跨域的情况下，服务器又需要响应一个正常的JSON格式  
2. </font>**<font style="color:rgb(38, 38, 38);">只能完成GET请求</font>**<font style="color:rgb(38, 38, 38);">：JSONP的原理会要求浏览器端生成一个script元素，而script元素发出的请求只能是get请求  
所以，CORS是一种更好的跨域解决方案。</font>

# **<font style="color:rgb(38, 38, 38);">概述</font>**
<font style="color:rgb(38, 38, 38);">CORS</font><font style="color:rgb(38, 38, 38);">是基于</font><font style="color:rgb(38, 38, 38);">http1.1</font><font style="color:rgb(38, 38, 38);">的一种跨域解决方案，它的全称是</font>**<font style="color:rgb(38, 38, 38);">C</font>**<font style="color:rgb(38, 38, 38);">ross-</font>**<font style="color:rgb(38, 38, 38);">O</font>**<font style="color:rgb(38, 38, 38);">rigin </font>**<font style="color:rgb(38, 38, 38);">R</font>**<font style="color:rgb(38, 38, 38);">esource </font>**<font style="color:rgb(38, 38, 38);">S</font>**<font style="color:rgb(38, 38, 38);">haring，跨域资源共享。</font><font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">它的总体思路是：</font>**<font style="color:rgb(38, 38, 38);">如果浏览器要跨域访问服务器的资源，需要获得服务器的允许</font>**<font style="color:rgb(38, 38, 38);">  
</font>

![](https://cdn.nlark.com/yuque/0/2021/png/1618242/1610097882847-5b217f20-192f-4d2c-8559-3b5daff55706.png?x-oss-process=image%2Fwatermark%2Ctype_d3F5LW1pY3JvaGVp%2Csize_21%2Ctext_d3d3Lnl1cXVlLmNvbS95bXdhbmc%3D%2Ccolor_FFFFFF%2Cshadow_50%2Ct_80%2Cg_se%2Cx_10%2Cy_10%2Fresize%2Cw_732%2Climit_0)

<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">而要知道，一个请求可以附带很多信息，从而会对服务器造成不同程度的影响  
</font><font style="color:rgb(38, 38, 38);">比如有的请求只是获取一些新闻，有的请求会改动服务器的数据  
</font><font style="color:rgb(38, 38, 38);">针对不同的请求，CORS规定了三种不同的交互模式，分别是：  
</font>**<font style="color:rgb(38, 38, 38);">●简单请求</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">●需要预检的请求</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">●附带身份凭证的请求</font>**<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">这三种模式从上到下层层递进，请求可以做的事越来越多，要求也越来越严格。  
</font><font style="color:rgb(38, 38, 38);">下面分别说明三种请求模式的具体规范。</font>

# **<font style="color:rgb(38, 38, 38);">简单请求</font>**
<font style="color:rgb(38, 38, 38);">当浏览器端运行了一段ajax代码（无论是使用XMLHttpRequest还是fetch api），浏览器会首先判断它属于哪一种请求模式</font>

## **<font style="color:rgb(38, 38, 38);">简单请求的判定</font>**
<font style="color:rgb(38, 38, 38);">当请求</font>**<font style="color:rgb(38, 38, 38);">同时满足</font>**<font style="color:rgb(38, 38, 38);">以下条件时，浏览器会认为它是一个简单请求：</font>

<font style="color:rgb(38, 38, 38);"></font>

### **<font style="color:rgb(38, 38, 38);">1. 请求方法属于下面的一种：</font>**
<font style="color:rgb(38, 38, 38);">●get  
</font><font style="color:rgb(38, 38, 38);">●post  
</font><font style="color:rgb(38, 38, 38);">●head</font>

### <font style="color:rgb(38, 38, 38);">2. 请求头仅包含安全的字段，常见的安全字段如下：</font>
<font style="color:rgb(38, 38, 38);">●Accept  
</font><font style="color:rgb(38, 38, 38);">●Accept-Language  
</font><font style="color:rgb(38, 38, 38);">●Content-Language  
</font><font style="color:rgb(38, 38, 38);">●Content-Type  
</font><font style="color:rgb(38, 38, 38);">●DPR  
</font><font style="color:rgb(38, 38, 38);">●Downlink  
</font><font style="color:rgb(38, 38, 38);">●Save-Data  
</font><font style="color:rgb(38, 38, 38);">●Viewport-Width  
</font><font style="color:rgb(38, 38, 38);">●Width</font>

### **<font style="color:rgb(38, 38, 38);"> 3. 请求头如果包含Content-Type，仅限下面的值之一：</font>**
<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">text/plain  
</font><font style="color:rgb(38, 38, 38);">●multipart/form-data  
</font><font style="color:rgb(38, 38, 38);">●application/x-www-form-urlencoded  
</font><font style="color:rgb(38, 38, 38);">如果以上三个条件同时满足，浏览器判定为简单请求。  
</font><font style="color:rgb(38, 38, 38);">下面是一些例子：</font>

```php
// 简单请求
fetch("http://crossdomain.com/api/news");

// 请求方法不满足要求，不是简单请求
fetch("http://crossdomain.com/api/news", {
  method:"PUT"
})

// 加入了额外的请求头，不是简单请求
fetch("http://crossdomain.com/api/news", {
  headers:{
    a: 1
  }
})

// 简单请求
fetch("http://crossdomain.com/api/news", {
  method: "post"
})

// content-type不满足要求，不是简单请求
fetch("http://crossdomain.com/api/news", {
  method: "post",
  headers: {
    "content-type": "application/json"
  }
})
```

## **<font style="color:rgb(38, 38, 38);">简单请求的交互规范</font>**
<font style="color:rgb(38, 38, 38);">当浏览器判定某个</font>**<font style="color:rgb(38, 38, 38);">ajax跨域请求</font>**<font style="color:rgb(38, 38, 38);">是</font>**<font style="color:rgb(38, 38, 38);">简单请求</font>**<font style="color:rgb(38, 38, 38);">时，会发生以下的事情</font>

### **<font style="color:rgb(38, 38, 38);">1. 请求头中会自动添加Origin字段</font>**
<font style="color:rgb(38, 38, 38);">比如，在页面</font>`[<font style="color:rgb(38, 38, 38);">http://my.com/index.html</font>](http://my.com/index.html)`<font style="color:rgb(38, 38, 38);">中有以下代码造成了跨域</font>

```php
// 简单请求
fetch("http://crossdomain.com/api/news");
```

<font style="color:rgb(38, 38, 38);">请求发出后，请求头会是下面的格式：</font>

```php
GET /api/news/ HTTP/1.1
Host: crossdomain.com
Connection: keep-alive
...
Referer: http://my.com/index.html
Origin: http://my.com
```

<font style="color:rgb(38, 38, 38);">看到最后一行没，Origin字段会告诉服务器，是哪个源地址在跨域请求</font>

### <font style="color:rgb(38, 38, 38);">2. 服务器响应头中应包含Access-Control-Allow-Origin</font>
<font style="color:rgb(38, 38, 38);">当服务器收到请求后，如果允许该请求跨域访问，需要在响应头中添加Access-Control-Allow-Origin字段  
</font><font style="color:rgb(38, 38, 38);">该字段的值可以是：  
</font><font style="color:rgb(38, 38, 38);">●</font>`<font style="color:rgb(38, 38, 38);">*</font>`<font style="color:rgb(38, 38, 38);">：表示我很开放，什么人我都允许访问  
</font><font style="color:rgb(38, 38, 38);">●具体的源：比如</font>`[<font style="color:rgb(38, 38, 38);">http://my.com</font>](http://my.com/)`<font style="color:rgb(38, 38, 38);">，表示我就允许你访问  
</font><font style="color:rgb(38, 38, 38);">实际上，这两个值对于客户端</font>`[<font style="color:rgb(38, 38, 38);">http://my.com</font>](http://my.com/)`<font style="color:rgb(38, 38, 38);">而言，都一样，因为客户端才不会管其他源服务器允不允许，就关心自己是否被允许  
</font><font style="color:rgb(38, 38, 38);">当然，服务器也可以维护一个可被允许的源列表，如果请求的Origin命中该列表，才响应</font>`<font style="color:rgb(38, 38, 38);">*</font>`<font style="color:rgb(38, 38, 38);">或具体的源  
</font>**<font style="color:rgb(38, 38, 38);">为了避免后续的麻烦，强烈推荐响应具体的源</font>**<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">假设服务器做出了以下的响应：</font>

```php
HTTP/1.1 200 OK
Date: Tue, 21 Apr 2020 08:03:35 GMT
...
Access-Control-Allow-Origin: http://my.com
...

消息体中的数据
```

<font style="color:rgb(38, 38, 38);">当浏览器看到服务器允许自己访问后，高兴的像一个两百斤的孩子，于是，它就把响应顺利的交给js，以完成后续的操作</font><font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">下图简述了整个交互过程</font><font style="color:rgb(38, 38, 38);">  
</font>

![](https://cdn.nlark.com/yuque/0/2021/png/1618242/1610097882967-cf70c31c-01d0-42b2-bbb0-0d2bf0cbde8e.png?x-oss-process=image%2Fwatermark%2Ctype_d3F5LW1pY3JvaGVp%2Csize_29%2Ctext_d3d3Lnl1cXVlLmNvbS95bXdhbmc%3D%2Ccolor_FFFFFF%2Cshadow_50%2Ct_80%2Cg_se%2Cx_10%2Cy_10%2Fresize%2Cw_937%2Climit_0)

## **<font style="color:rgb(38, 38, 38);">代码示例</font>**<font style="color:rgb(38, 38, 38);">  
</font>
# **<font style="color:rgb(38, 38, 38);">需要预检的请求</font>**
<font style="color:rgb(38, 38, 38);">简单的请求对服务器的威胁不大，所以允许使用上述的简单交互即可完成。  
</font><font style="color:rgb(38, 38, 38);">但是，如果浏览器不认为这是一种简单请求，就会按照下面的流程进行：  
</font>**<font style="color:rgb(38, 38, 38);">1浏览器发送预检请求，询问服务器是否允许</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">2服务器允许</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">3浏览器发送真实请求</font>**<font style="color:rgb(38, 38, 38);">  
</font>**<font style="color:rgb(38, 38, 38);">4服务器完成真实的响应</font>**<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">比如，在页面</font>`[<font style="color:rgb(38, 38, 38);">http://my.com/index.html</font>](http://my.com/index.html)`<font style="color:rgb(38, 38, 38);">中有以下代码造成了跨域</font>

```php
// 需要预检的请求
fetch("http://crossdomain.com/api/user", {
  method:"POST", // post 请求
  headers:{  // 设置请求头
    a: 1,
    b: 2,
    "content-type": "application/json"
  },
  body: JSON.stringify({ name: "袁小进", age: 18 }) // 设置请求体
});
```

<font style="color:rgb(38, 38, 38);">浏览器发现它不是一个简单请求，则会按照下面的流程与服务器交互</font>

## **<font style="color:rgb(38, 38, 38);">浏览器发送预检请求，询问服务器是否允许</font>**
```php
OPTIONS /api/user HTTP/1.1
Host: crossdomain.com
...
Origin: http://my.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: a, b, content-type
```

<font style="color:rgb(38, 38, 38);">可以看出，这并非我们想要发出的真实请求，请求中不包含我们的响应头，也没有消息体。  
</font><font style="color:rgb(38, 38, 38);">这是一个预检请求，它的目的是询问服务器，是否允许后续的真实请求。  
</font><font style="color:rgb(38, 38, 38);">预检请求</font>**<font style="color:rgb(38, 38, 38);">没有请求体</font>**<font style="color:rgb(38, 38, 38);">，它包含了后续真实请求要做的事情  
</font><font style="color:rgb(38, 38, 38);">预检请求有以下特征：  
</font><font style="color:rgb(38, 38, 38);">●请求方法为OPTIONS  
</font><font style="color:rgb(38, 38, 38);">●没有请求体  
</font><font style="color:rgb(38, 38, 38);">●请求头中包含  
</font><font style="color:rgb(38, 38, 38);">○Origin：请求的源，和简单请求的含义一致  
</font><font style="color:rgb(38, 38, 38);">○Access-Control-Request-Method：后续的真实请求将使用的请求方法  
</font><font style="color:rgb(38, 38, 38);">○Access-Control-Request-Headers：后续的真实请求会改动的请求头</font>

## **<font style="color:rgb(38, 38, 38);">服务器允许</font>**
<font style="color:rgb(38, 38, 38);">服务器收到预检请求后，可以检查预检请求中包含的信息，如果允许这样的请求，需要响应下面的消息格式</font>

```php
HTTP/1.1 200 OK
Date: Tue, 21 Apr 2020 08:03:35 GMT
...
Access-Control-Allow-Origin: http://my.com
Access-Control-Allow-Methods: POST
Access-Control-Allow-Headers: a, b, content-type
Access-Control-Max-Age: 86400
...
```

<font style="color:rgb(38, 38, 38);">对于预检请求，不需要响应任何的消息体，只需要在响应头中添加：  
</font><font style="color:rgb(38, 38, 38);">●</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Allow-Origin</font>`<font style="color:rgb(38, 38, 38);">：和简单请求一样，表示允许的源  
</font><font style="color:rgb(38, 38, 38);">●</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Allow-Methods</font>`<font style="color:rgb(38, 38, 38);">：表示允许的后续真实的请求方法  
</font><font style="color:rgb(38, 38, 38);">●</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Allow-Headers</font>`<font style="color:rgb(38, 38, 38);">：表示允许改动的请求头  
</font><font style="color:rgb(38, 38, 38);">●</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Max-Age</font>`<font style="color:rgb(38, 38, 38);">：告诉浏览器，多少秒内，对于同样的请求源、方法、头，都不需要再发送预检请求了</font>

## **<font style="color:rgb(38, 38, 38);">浏览器发送真实请求</font>**
<font style="color:rgb(38, 38, 38);">预检被服务器允许后，浏览器就会发送真实请求了，上面的代码会发生下面的请求数据  
</font>

```php
POST /api/user HTTP/1.1
Host: crossdomain.com
Connection: keep-alive
...
Referer: http://my.com/index.html
Origin: http://my.com

{"name": "袁小进", "age": 18 }
```

## <font style="color:rgb(38, 38, 38);"> </font>**<font style="color:rgb(38, 38, 38);">服务器响应真实请求</font>**
```php
HTTP/1.1 200 OK
Date: Tue, 21 Apr 2020 08:03:35 GMT
...
Access-Control-Allow-Origin: http://my.com
...

添加用户成功
```

<font style="color:rgb(38, 38, 38);">可以看出，当完成预检之后，后续的处理与简单请求相同</font><font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">下图简述了整个交互过程</font><font style="color:rgb(38, 38, 38);">  
</font>

# **<font style="color:rgb(38, 38, 38);">附带身份凭证的请求</font>**
<font style="color:rgb(38, 38, 38);">默认情况下，ajax的跨域请求并不会附带cookie，这样一来，某些需要权限的操作就无法进行  
</font><font style="color:rgb(38, 38, 38);">不过可以通过简单的配置就可以实现附带cookie</font>

```php
// xhr
var xhr = new XMLHttpRequest();
xhr.withCredentials = true;

// fetch api
fetch(url, {
  credentials: "include"
})
```

<font style="color:rgb(38, 38, 38);">这样一来，该跨域的ajax请求就是一个</font>_<font style="color:rgb(38, 38, 38);">附带身份凭证的请求</font>_<font style="color:rgb(38, 38, 38);">  
</font><font style="color:rgb(38, 38, 38);">当一个请求需要附带</font>`<font style="color:rgb(38, 38, 38);">cookie</font>`<font style="color:rgb(38, 38, 38);">时，无论它是简单请求，还是预检请求，都会在请求头中添加cookie字段  
</font><font style="color:rgb(38, 38, 38);">而服务器响应时，需要明确告知客户端：服务器允许这样的凭据  
</font><font style="color:rgb(38, 38, 38);">告知的方式也非常的简单，只需要在响应头中添加：</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Allow-Credentials: true</font>`<font style="color:rgb(38, 38, 38);">即可  
</font><font style="color:rgb(38, 38, 38);">对于一个附带身份凭证的请求，若服务器没有明确告知，浏览器仍然视为跨域被拒绝。  
</font><font style="color:rgb(38, 38, 38);">另外要特别注意的是：</font>**<font style="color:rgb(38, 38, 38);">对于附带身份凭证的请求，服务器不得设置 </font>**`**<font style="color:rgb(38, 38, 38);">Access-Control-Allow-Origin 的值为*</font>**`<font style="color:rgb(38, 38, 38);">。这就是为什么不推荐使用*的原因</font>

# **<font style="color:rgb(38, 38, 38);">一个额外的补充</font>**
<font style="color:rgb(38, 38, 38);">在跨域访问时，JS只能拿到一些最基本的响应头，如：Cache-Control、Content-Language、Content-Type、Expires、Last-Modified、Pragma，如果要访问其他头，则需要服务器设置本响应头。  
</font>`<font style="color:rgb(38, 38, 38);">Access-Control-Expose-Headers</font>`<font style="color:rgb(38, 38, 38);">头让服务器把允许浏览器访问的头放入白名单，例如：</font>

```php
Access-Control-Expose-Headers: authorization, a, b
```

<font style="color:rgb(38, 38, 38);">这样JS就能够访问指定的响应头了。</font>
